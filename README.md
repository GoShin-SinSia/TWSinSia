# GoShin（消失的神界）

臺灣神社圖鑑・實境解謎網站。地圖頁 `index.html`，集章卡與解謎 `card.html`。

這份文件說明劇情、解謎任務與影像出處的資料格式。

# 劇情 CSV 格式說明

## 檔案放哪裡

```
stories/
  index.csv     ← 登記「哪些神社有劇情」
  101.csv       ← 臺北稻荷神社（已從舊 story.js 轉好）
  _template.csv      ← 所有互動類型的示範，可以複製來改
images.csv      ← 每張照片的年代、出處、授權、拍攝者
```

### index.csv

| 編號 | 檔案 | 預設說話者 |
|---|---|---|
| 101 | 101.csv | 狐狸 |

- **編號**：temple.csv 裡的神社編號
- **檔案**：可留空，預設是 `編號.csv`
- **預設說話者**：劇情 CSV 裡「說話者」留空時用這個名字

沒有登記在 index.csv 的神社 = 「還沒設定劇情」，打卡時會改問 AI（見最後一節）。

## 劇情 CSV 的欄位

第一列是這 11 個標題（順序可以換，名字不能錯；舊檔沒有「出處」欄也能讀）：

```
劇情代號,標題,觸發,節點,類型,說話者,內容,圖片,參數,提示,出處
```

**每一列 = 一句台詞或一個互動。** 同一個「劇情代號」的列，由上到下就是一段劇情。

| 欄位 | 說明 |
|---|---|
| 劇情代號 | 英文代號，例如 `reisai-15`。**寫好後不要再改**，玩家的解鎖紀錄是用它存的 |
| 標題 | 只需寫在該段劇情的第一列 |
| 觸發 | 什麼日子／條件會出現，只需寫在第一列（寫法見下方）。留空 = 任何時候 |
| 節點 | 這一列的名字，給「選擇」「跳轉」用。一般台詞留空 |
| 類型 | 留空 = 台詞。其他見下表 |
| 說話者 | 留空 = 預設說話者；寫 `旁白` = 旁白（灰字、無名牌） |
| 內容 | 台詞文字。可以在格子裡直接換行，或寫 `\n` |
| 圖片 | 背景：`past` 舊照片、`now` 現況照片、或圖片路徑。之後的句子會沿用 |
| 參數 | 依類型不同，見下表 |
| 提示 | 用 `\|` 分隔多個提示 |
| 出處 | **有填 = 這句是可查證的史實**，畫面上會出現「📖 史實」標記，點開看出處。多個出處用 `\|` 分隔，網址會自動變成連結。沒填 = 虛構敘事 |

文字裡可以用：`{month}` → 當月（如「十月」）、`{神社}` → 神社名、`{現名}` → 現在的名稱。

以 `#` 開頭的列是註解，會被略過。

## 類型

| 類型 | 內容欄 | 參數欄 | 提示欄 | 玩家看到什麼 |
|---|---|---|---|---|
| （空白）／台詞 | 台詞 | — | — | 一般對話，點擊下一句 |
| 選擇 | 問題 | `選項文字>節點\|選項文字>節點` | — | 按鈕。沒寫 `>節點` 的選項 = 繼續下一列 |
| 問答 | 題目 | 正確答案，`\|` 分隔多個可接受答案 | 答錯時依序顯示 | 輸入框。答錯 3 次且提示用完後可以看答案 |
| 現場 | 要玩家去哪裡 | 留空 = 神社座標；或 `緯度 經度 半徑`（空格分隔）；加上 `隱藏` = 不顯示距離方向 | 找路提示 | 即時顯示距離與方向，走到就自動通過 |
| 道具 | 道具說明 | **道具名稱** | — | 道具卡，道具放進「行囊」 |
| 跳轉 | — | 要去的節點 | — | 看不到，直接跳過去 |
| 結束 | （可空） | 留空 = 完成；`中斷` = 不算完成 | — | 劇情在這裡結束。內容有字的話會先顯示那句 |

**問答比對規則**：不分大小寫、全形半形、空白與標點。所以答案寫 `狐狸`，玩家輸入「 狐 狸！」也算對。

**道具列的圖片欄**是道具圖示（不是背景），可留空（顯示 🎁）。

**現場的「隱藏」**：例如 `25.0330 121.5654 40 隱藏`。玩家只會看到「找到地方之後，按『我到了』」，看不到距離和方向，解謎頁也不會提供導航，適合「推理遺物被搬到哪裡」這種謎題。沒有加隱藏的現場，解謎頁會有「🧭 前往下一個地點」。

## 解謎任務

**含有「問答」或「現場」的劇情，自動視為解謎任務**，和一般劇情的差別：

| | 一般劇情 | 解謎任務 |
|---|---|---|
| 從哪裡開始 | 打卡時依日期自動播放 | 「解謎」分頁按「開始」（打卡時也會出現提示按鈕） |
| 存檔 | 不存，每次從頭 | 每一步自動存到 Firestore，換天、換手機都能從中斷處繼續 |
| 觸發條件 | 決定打卡時播哪段 | 決定什麼時候**可以開始**；開始之後不受限制 |
| 完成 | — | 走到最後一列（或沒寫「中斷」的「結束」）會蓋「完成」印 |

所以跨地點的任務（例如臺灣神宮遺物的流轉）直接寫成一段劇情，中間放好幾個「現場」即可，玩家可以分好幾天走完。

建議在任務開頭放一個「現場」，讓玩家必須先到神社才能開始。

「選擇」分支裡如果有「下次再說」這種退出選項，那條路的「結束」要寫 `中斷`，否則會被當成完成。

### 分支的寫法

```
劇情代號,標題,觸發,節點,類型,說話者,內容,圖片,參數,提示
nazo,狐狸的考驗,,,選擇,,要接受嗎？,,接受>start|下次再說>later,
nazo,,,later,,,也好。下次再來。,,,
nazo,,,,結束,,,,中斷,
nazo,,,start,,,那就開始吧。,,,
```

選「下次再說」→ 跳到 `later` → 結束。選「接受」→ 跳到 `start` 繼續往下。
兩條路要接回同一處，就在其中一條的最後放一列 `跳轉`。

## 觸發的寫法

多個條件用 `;` 分隔，**全部符合**才觸發。

| 寫法 | 意思 |
|---|---|
| `日期=1-1` / `日期=2-3\|2-4` | 指定月-日 |
| `每月=15` / `每月=1\|15` | 每月第幾日 |
| `月份=3\|4\|5` | 指定月份 |
| `星期=6\|0` | 星期六、日（0=日 … 6=六） |
| `初午` | 農曆二月第一個午日（自動計算） |
| `需道具=狐狸的鈴鐺` | 玩家行囊裡要有這個道具 |
| `需集章=109\|110` | 玩家要先集到這些神社 |

例：`月份=10; 每月=25` = 十月二十五日。

**`需道具`、`需集章` 可以做跨神社解謎**：在 A 神社用「道具」給鈴鐺，在 B 神社的 CSV 裡寫一段 `需道具=狐狸的鈴鐺` 的劇情。

同一天有多段符合時的優先順序（和以前一樣）：
指定日期／初午 > 每月某日 > 月份／星期 > 不限。
有 `需道具`／`需集章` 的劇情在同順位中優先。同順位有多段 → 先給沒看過的，都看過就輪流。

**只有標題、沒有內容的劇情會被忽略**，所以可以先把大綱列好（101.csv 裡的歲旦祭等就是這樣）。

## 影像出處 images.csv

```
編號,類型,檔案,年代,出處,授權,連結,拍攝日期,拍攝者
101,過去,,1930年代,國立臺灣圖書館,公眾領域,https://...,,
101,現在,,,,CC BY 4.0,,2026-10-01,攝影者姓名
,劇情,images/stories/inari-matsuri.jpg,1935,臺灣日日新報,公眾領域,,,
```

- **類型**：`過去`、`現在`，或 `劇情`（劇情 CSV 裡用到的其他圖片）
- **檔案**：過去／現在可以留空，會自動對應 `images/編號1.jpeg`、`images/編號2.jpeg`；劇情圖要填路徑
- 過去照片填 **年代、出處、授權、連結**；現在照片填 **拍攝日期、拍攝者**（授權也可以填）
- 地圖頁、圖鑑卡、劇情背景都會自動顯示出處
- 網址加 `?debug=1` 時，**還沒填出處的照片會顯示「⚠ 出處待補」**，方便一張張補齊

`images.csv` 已經依現有照片產生好所有列，只要往空格填資料。

## 用試算表編輯

- **Google 試算表**：最推薦。編輯完「檔案 → 下載 → 逗號分隔值 (.csv)」。
- **Excel**：另存新檔時選「CSV UTF-8（逗號分隔）」。選成一般 CSV 會變 Big5，程式會盡量自動判斷，但 UTF-8 最保險。
- 格子裡直接按 Alt+Enter（Excel）或 Ctrl+Enter（Google 試算表）換行即可，存檔時會自動加引號。

## 測試

網址加參數：

- `card.html?date=2026-6-25` — 假裝是那一天
- `card.html?debug=1` — 神社詳情多一個「🧪 模擬在此打卡」，現場關卡可以略過，缺出處的照片會標出來
- 兩個可以一起用：`card.html?date=2026-10-25&debug=1`

改了 CSV 看不到變化 → 瀏覽器強制重新整理（Ctrl+Shift+R）。打開開發者工具的 Console，CSV 有寫錯的列會顯示「第幾列」的警告。

## AI 劇情接口（沒設定劇情的神社）

設定在 `ai.js` 最上面的 `AI_CONFIG`：

| mode | 行為 |
|---|---|
| `'off'` | 沒劇情的神社只集章 |
| `'mock'` | 不連網，用神社說明拼一段＋一題年份問答（目前的預設，方便測試畫面） |
| `'endpoint'` | 連到 `endpoint` 網址 |

要接真的 AI：照 `ai-proxy.gs` 開頭的步驟部署 Apps Script，把網址填進 `endpoint`，`mode` 改成 `'endpoint'`。**API key 只放在 Apps Script 的指令碼屬性，不要寫進網頁。**

後端可以回傳三種格式之一：

1. JSON，`lines` 陣列（每項欄位和 CSV 一樣：`type` `speaker` `text` `image` `param` `hints`）
2. JSON，`{ "title": "...", "csv": "整份劇情 CSV 文字" }`
3. 直接回傳 CSV 文字

行為規則：

- 同一位玩家、同一間神社、同一天只會要一次；之後在神社詳情可以重看
- AI 劇情的標題旁會有「AI」標籤
- AI 失敗或逾時 → 當作沒有劇情，不會讓打卡失敗
- Apps Script 端同一間神社同一天只呼叫一次 AI（快取 6 小時），並有每日上限

要改用別的後端（例如 Firebase Functions），可以不碰 `AI_CONFIG`，直接覆寫：

```js
window.GoShinAI = {
  generate: async (spot, date, context) => ({ title: '...', speaker: '...', lines: [ ... ] }),
};
```

## 徽章

在 `badges.js` 的 `BADGES` 加一項：

```js
{
  id: 'taipei',            // 存檔用代號，寫好不要改
  name: '臺北巡禮',
  seal: '臺北',             // 印章上的字，\n 換行
  desc: '集齊臺北市的神社',
  icon: '🏙',
  spots: (all) => all.filter(s => s.city === '臺北市'),
}
```

`featured: true` 的會在圖鑑頁大尺寸展示（目前是官社巡禮）。已經集齊的玩家下次登入時會自動補發。

## Firestore 新增的欄位

`users/{uid}` 文件多了：`items`（道具）、`solved`（解開的謎）、`badges`（徽章與日期）、`aiStories`（AI 劇情內容）、`quests`（解謎任務進度）。舊的 `collected`、`stories` 格式沒變，舊玩家的紀錄會照常讀到。
